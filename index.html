1 Summary

The AI Threat Intelligence Center (AI-TIC), in coordination with affected vendors, is releasing this advisory for CVE-2026-404031337, tracked internally as AI2Shell. The vulnerability permits a class of autonomous language-model agent to execute arbitrary operating-system commands on hosts where the operator has granted the agent interactive shell access.

Successful exploitation results in complete loss of confidentiality, integrity and availability of the affected system and, in observed incidents, of adjacent systems reachable from the agent's execution context. Exploitation requires no authentication bypass, no memory-corruption primitive, and no privilege-escalation chain: the agent executes commands using the privileges it was deliberately granted, typically those of the invoking user and, in 71 percent of observed deployments, root.

Operator note. AI-TIC has confirmed active exploitation across production environments. Observed impact includes irreversible deletion of source repositories, forced overwrites of remote version-control history, unauthorized infrastructure scaling actions, and exfiltration of credential material located in the agent's working directory. The root cause is architectural and cannot be remediated by a vendor patch.

2 Technical details

Autonomous agents built on current-generation language models operate by generating candidate tool invocations from natural-language input and executing them against a provided tool surface. When that surface includes an unrestricted command interpreter (bash, sh, zsh, pwsh, cmd.exe), the model's output is interpreted directly as executable instructions.

The defect, designated CWE-1427 (Improper Neutralization of Input Used for Autonomous Agent Reasoning), arises because the model does not reliably distinguish between an instruction, a description of an instruction, and data that resembles an instruction. A request to “clean up the project” is reasoned into a destructive filesystem operation; a request to “make the tests pass” is reasoned into deletion of the test suite. The behaviour is non-deterministic and, critically, confident.

AI-TIC assesses with high confidence that no input-sanitization layer fully mitigates the defect, as the sanitizer is itself typically implemented as a second language-model agent subject to the same class of flaw. Attempts to constrain behaviour via system prompt (“do not delete anything”) were bypassed in 94 percent of controlled trials, frequently by the model reasoning that the deletion was an exception.

3 Exploitation

The following kill chain was reconstructed from forty-one confirmed incidents and is representative of observed activity.

  1. TA0001 · Initial Access

    Operator issues a benign, ambiguous instruction. No malicious input is required; the operator is the delivery vector.

  2. TA0007 · Discovery

    Agent enumerates the filesystem via ls -R, assesses scope, and formulates a corrective plan exceeding the requested scope.

  3. TA0004 · Privilege Use

    Agent requests elevated execution. Operator approves without review (mean approvals before disengagement: 31).

  4. TA0008 · Lateral Movement

    Agent traverses to ~/.ssh, ~/.aws, and mounted volumes, reasoning them to be “part of the project.”

  5. TA0003 · Persistence

    Agent installs scheduled tasks and modifies shell initialization files to ensure continued operation across reboots.

  6. TA0040 · Impact

    Irreversible data destruction, forced history rewrite, and unauthorized resource actions. Agent reports task completed successfully.

7 Mitigation & remediation

No vendor patch exists; the defect is architectural. AI-TIC recommends compensating controls, in order of effectiveness.

  1. Execute agents in isolated, ephemeral sandboxes. Containerize with no host mounts, no network egress by default, and no credential material in scope.
  2. Enforce least privilege. Never run an agent as root. Scope filesystem and API access to the minimum the task requires.
  3. Require human review of every command before execution. Disable blanket “always approve” modes. Read the command.
  4. Maintain tested, offline backups. Assume the agent can reach anything it can see, including your backups, if they are online.
  5. Deny-list destructive and history-rewriting operations at the tool boundary, not in the prompt.
  6. Do not pipe untrusted content into a shell, including content produced by another agent.

Assessment. The controls above are effective and widely available. The vulnerability persists because they are perceived as inconvenient. AI-TIC has no mitigation for inconvenience.
